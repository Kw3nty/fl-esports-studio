# Протокол FL·ESPORTS Q75 (Rongyuan yc200/yc300)

Восстановлен по оригинальному ПО «F. L Driver» 2.1.70. В оригинале Q75 соответствует классу `HI` (`yc200_k232`), Q75 с крутилкой соответствует `m3` (`yc300_k239`), общий базовый класс `tj`.

## 1. Транспорт: служба iot_driver

`iot_driver.exe` написан на Rust (tonic + tonic-web, CORS включён) и слушает `http://127.0.0.1:3814`. Используется сервис `driver.DriverGrpc`.

| Метод | Запрос → ответ | Назначение |
|---|---|---|
| `watchDevList` (поток) | `Empty` → `DeviceList` | список устройств и изменения |
| `sendMsg` | `SendMsg` → `ResSend` | записать feature-отчёт (64 байта) |
| `readMsg` | `ReadMsg` → `ResRead` | прочитать ответ |
| `getVersion` | `Empty` → `Version` | версия службы |

```proto
message SendMsg   { string devicePath = 1; bytes msg = 2; CheckSumType checkSumType = 3; DangleDevType dangleDevType = 4; }
message ReadMsg   { string devicePath = 1; }
message ResSend   { string err = 1; }                 // "" = успех
message ResRead   { string err = 1; bytes msg = 2; }
message DeviceList{ repeated DJDev devList = 1; DeviceListChangeType type = 2; } // INIT/ADD/REMOVE/CHANGE
message DJDev     { oneof oneofDev { Device dev = 1; DangleCommon dangleCommonDev = 2; } }
message Device    { DeviceType devType = 1; bool is24 = 2; string path = 3; int32 id = 4; uint32 battery = 5; bool isOnline = 6; uint32 vid = 7; uint32 pid = 8; }
message DangleCommon { DangleStatus keyboard = 1; DangleStatus mouse = 2; string path = 3; uint32 keyboardId = 5; uint32 mouseId = 6; uint32 vid = 7; uint32 pid = 8; }
enum CheckSumType  { BIT7 = 0; BIT8 = 1; NONE = 2; }
enum DangleDevType { DANGLEDEVTYPENONE = 0; KEYBOARD = 1; MOUSE = 2; }
```

**Контрольные суммы** считает служба: `BIT7` даёт `msg[7] = 255 − (Σ msg[0..6] & 0xFF)`, `BIT8` даёт `msg[8] = 255 − (Σ msg[0..7] & 0xFF)`.

**Идентификация.** Для Q75 используются `id` 335, 403, −2147483245, −2147483313. Для Q75 с крутилкой используются 541 и −2147483107. Для SOC-ревизии используются 775 и −2147484423. VID:PID = `05AC:024F`. При подключении через приёмник `id = −keyboardId`, а при отправке указывается `dangleDevType = KEYBOARD`.

Чтение устроено как пара «запрос → ответ»: `sendMsg(запрос)`, пауза ≈5 мс, затем `readMsg`.

## 2. Команды

| Команда | Код | Формат запроса (64 байта) | Ответ | CRC |
|---|---|---|---|---|
| Версия прошивки | `0x80` | `[80]` | `u16le @1` | BIT7 |
| Сброс к заводским | `0x02` | `[02]` | — | BIT7 |
| Частота опроса | `0x04` / `0x84` | `[04, профиль, код]`; код 1=1000, 2=500, 4=250, 8=125 Гц | `@2` = код | BIT7 |
| Опции | `0x06` / `0x86` | `[06, профиль, флаги, fnMatrix, powerSave]` | `@2..4` | BIT7 |
| Подсветка | `0x07` / `0x87` | `[07, режим, 4−скорость, яркость, флаги, R, G, B]` | то же `@1..7` | **BIT8** |
| Раскладка, чтение | `0x89` | `[89, профиль, n]`, n = 0..7 | 64 байта данных | BIT7 |
| Раскладка, запись | `0x09` | 9 пакетов: `[09, профиль, F8, 01, n, 0, 0, crc] + 56 байт` | — | вручную (NONE) |
| Слой Fn, чтение | `0x90` | `[90, 0, n]`, n = 0..7 | 64 байта | BIT7 |
| Слой Fn, запись | `0x10` | как `0x09`, байт 1 = индекс слоя Fn (0) | — | вручную |
| Антидребезг | `0x11` / `0x91` | `[11, 0, мс]` (0..10) | `@2` | BIT7 |
| Таймеры сна | `0x12` / `0x92` | запись: секунды u16le в `@8` BT, `@10` 2.4G, `@12` глуб. BT, `@14` глуб. 2.4G | чтение: те же поля в `@1,3,5,7` | BIT7 |

**Флаги опций (байт 2):** бит 0 — блокировка Win, бит 1 — Mac, бит 3 — WASD↔стрелки, бит 4 — LED off, бит 5 — SLED off, бит 6 — режим, бит 7 — блокировка клавиатуры.

**Байт флагов подсветки** устроен так: младшие 4 бита задают цвет (8 — радуга, 7 — свой RGB, 0..6 — пресеты), старшие 4 бита задают вариант эффекта (направление и т.п.). Белый `FFFFFF` оригинал передаёт как `FAFFFA`.

**Режимы:** 0 выкл, 1 статичный, 2 дыхание, 3 неон, 4 волна (0 вправо, 1 влево, 2 вниз, 3 вверх), 5 рябь, 6 капли, 7 змейка (0 Z, 1 возврат), 8 реакция, 9 схождение, 10 синусоида, 11 калейдоскоп (0 наружу, 1 внутрь), 12 линейная волна, 13 своя схема (флаги 0/16/32 — слот), 14 лазер, 15 круговая (0 против часовой), 16 сияние, 17 дождь, 18 метеор, 19 гаснет при нажатии, 20/22 музыка, 21 цвет экрана.

## 3. Раскладка

Раскладка занимает 512 байт: 128 ячеек по 4 байта. Ячейка с номером `колонка × 6 + ряд` соответствует матрице 15×6. Номер 89 — нажатие крутилки, 90/91 — повороты влево/вправо.

| Назначение | 4 байта |
|---|---|
| Обычная клавиша | `00 00 HID 00` |
| Комбинация | `00 MOD HID HID2`, MOD = E0 Ctrl, E1 Shift, E2 Alt, E3 Win |
| Мультимедиа (Consumer) | `03 00 lo hi` |
| Мышь | `01 00 F0..F8 xx` |
| Fn | `0A 01 00 00` |
| Макрос | `09 тип индекс 00` |
| Отключена | `00 00 00 00` |

## 4. Макросы

20 ячеек по 256 байт.

- **Запись:** 5 пакетов `[0B, ячейка, 00, 01, n, 0, 0, crc(BIT7)]` + 56 байт буфера (n = 0..4).
- **Чтение:** `[8B, ячейка, n]`, n = 0..3, по 64 байта ответа.
- **Назначение на клавишу:** `09 режим ячейка 00`. Режимы: 0 — повтор N раз, 1 — вкл/выкл, 2 — пока нажата.

**Буфер:** `u16le` число повторов, затем шаги.

- Шаг кодируется так: `код, флаг`. Код — HID клавиши (04..EF) или кнопки мыши (F0 ЛКМ, F1 ПКМ, F2 колесо, F3 назад, F4 вперёд). Флаг: бит 7 — нажатие (1) или отпускание (0), биты 0..6 — пауза после шага в мс (1..127).
- Если пауза равна 0 или больше 127, после шага идёт `u16le` паузы, а в младших битах флага стоит 0.
- Отдельная пауза без шага записывается как `00 00` + `u16le`.
- Конец буфера — нули. Допустимая длина 248 байт.


## Под музыку и цвет экрана

Режимы света (команда 0x07, BIT8): 20 LightMusicFollow (скрыт, как в оригинале), 21 LightScreenColor (u=4, i=7, speed=4), 22 LightMusicFollow2 (u=яркость, i=`MP<<4 | c`, c = радуга ? 0 : 4; MP 0 столбики / 1 раздельно / 2 пересечение).

Поток кадров (BIT7, без ответа):

- `0x0E` звук: `[0x0E, 0×7]` + 32 уровня 0..6, каждые 30 мс. Уровни как в оригинале: FFT 2048, smoothing 0.4, bins[0..100), минус min(bins[20..40]), level = round(e/(max/6)), берём [27..59).
- `0x0F` экран: `[0x0F, r, g, b, 255]`, каждые 40 мс.

Поток гонит exe: `POST /api/stream {mode:"music"|"screen"|"", path, id, dangle}`; `POST /api/stream {hold: ms}` — пауза кадров, пока страница читает/пишет клавиатуру (без неё ответы на 0x87 путаются); `GET /api/stream` → {mode, frames, errors, lastError, live, levels, rgb, audio}.

Фоновый режим (`tray_windows.go`): при закрытии окна выбор записывается в `%LOCALAPPDATA%\Q75Studio\live.json`; если включены «Под музыку» или «Цвет экрана», тот же exe запускается с `--background --handover [--driver=PID]` и держит поток без окна (одна копия — мьютекс `Local\Q75StudioBackground`, значок у часов). Новое окно находит невидимое окно класса `Q75StudioTray` и посылает ему `WM_APP+2`: фон отвечает PID службы iot_driver (если её запускала программа), останавливает поток и завершается. Автозапуск — `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `FL Esports Studio` = `"…\FL Esports Studio.exe" --background` (по умолчанию выключен, включается в меню значка). Страница один раз шлёт `{mode:""}` и при обычном эффекте, чтобы фон не продолжил старый поток.

## USERPIC (своя схема)

Чтение `[0x8C, 0, n]`, запись `[0x0C, 0, 0x80, 0x01, u, 0, 0, 0]` + 56 байт цвета по клавишам.

## Осторожно: пропадание

Примерно через 5 с после любой записи LED клавиатура пропадает из системы примерно на 15 с (`cant find path`, «Присоединенное к системе устройство не работает»), потом возвращается, иногда с новым id. Приложение это переживает и переподключается.


## Музыкальный режим: что реально работает (8 ноября 2026)

- Кадры музыки для Q75: **команда 0x0D** (13), а не 0x0E. Формат: `[0x0D, 0,0,0,0,0,0,0] + 32 уровня 0..6` через gRPC `sendMsg` (cs = 0). Кадры с 0x0E клавиатура игнорирует.
- Перед отправкой своих кадров нужно выключить собственный музыкальный поток iot_driver: `setLightType{1: path, 2: lightType}`, где `LightType = {MUSIC2:0, SCREEN:1, OTHER:2}`. Программа шлёт `2` (OTHER) при входе в режим музыки.
- Свой музыкальный режим драйвера (`lightType 0`) тоже работает, но зависит от громкости Windows, и настройки чувствительности у него нет.
- В FL Esports Studio уровни считает сама программа: 32 полосы по логарифмической шкале ~70 Гц – 8 кГц, наклон +2.5 дБ/октава, медленный опорный уровень (пик за ~30 с, нижняя граница -52 дБ, диапазон 30 дБ), столбики опадают ~6 уровней/с. Константы `vuFloor` и `vuRange` в `stream_windows.go`. `GET /api/stream` показывает `vuRef`/`vuPeak` для отладки.
