# Как помочь проекту

Спасибо за интерес к FL Esports Studio! Здесь описано, как собрать проект, проверить изменения и прислать pull request.

## Что понадобится

- Python 3.10+ (сборка HTML), Go 1.24+ (exe), Node.js 18+ (тесты и скриншоты);
- Windows 10 или 11, чтобы запускать exe. HTML, тесты и сборка exe работают на любой ОС;
- клавиатура не обязательна: есть демо-режим, мок службы `iot_driver` и симулятор прошивки.

## Быстрый старт

```powershell
python build.py                                   # dist\FLEsportsStudio.html
node test/unit.js
node test/userpic.js
Copy-Item dist\FLEsportsStudio.html launcher\ui\  # нужен для go:embed
cd launcher; go test ./...; cd ..
.\build.ps1                                       # exe и zip в release\
```

## Как устроен код

- **Интерфейс** написан на обычном JavaScript, без фреймворков и сборщиков. `build.py` подставляет `src/style.css` и скрипты в `src/index.html` и получает один файл `dist/FLEsportsStudio.html`. Порядок скриптов задан в `build.py`, новый файл нужно добавить туда.
- `src/core.js`: транспорт (gRPC-web к `iot_driver`) и протокол Q75. `src/keys.js`: коды клавиш и физическая раскладка. `src/app.js`: интерфейс. `src/kb3d.js`: 3D-клавиатура на three.js. `src/sim.js`: симулятор прошивки для демо и тестов.
- **launcher/** на Go: окно WebView2, поиск и запуск `iot_driver.exe`, локальный сервер и прокси на `127.0.0.1:38475`, захват звука и экрана для живых режимов (`stream_windows.go`), значок у часов и автозапуск (`tray_windows.go`).
- `launcher/rsrc_windows_amd64.syso` содержит иконку и манифест. Его нужно пересобрать, если меняется `icon.ico` или `app.manifest`.
- Протокол описан в [docs/PROTOCOL.md](docs/PROTOCOL.md). Если находите новую команду, дополните документ.

## Правила безопасности

Изменения, которые пишут в клавиатуру, должны соблюдать те же правила, что и остальной код:

- перед записью читать текущее состояние и менять только то, что выбрал пользователь;
- блокировать запись, если ответ клавиатуры выглядит неправильно;
- после записи читать данные повторно и сверять их;
- сохранять неизвестные биты как есть.

Команды обновления прошивки и загрузчика в проект не добавляются.

## Тесты

| Команда | Что проверяет |
|---|---|
| `node test/unit.js` | пакеты, контрольные суммы, форматы раскладки и макросов |
| `node test/userpic.js` | своя схема (`SET_USERPIC`) |
| `go test ./...` в `launcher/` | сервер и прокси |
| `node test/e2e.js` | весь путь: HTML → gRPC-web → мок службы → симулятор прошивки |

Для `e2e.js` установите Playwright (`npm i --no-save playwright` и `npx playwright install chromium`) или укажите свой Chrome в `CHROMIUM_PATH`. Мок занимает порт `3814`, поэтому перед запуском остановите настоящую службу (`scripts\Остановить службу.bat`). Скриншоты теста сохраняются во временную папку `q75-e2e`.

## Скриншоты

Если менялся внешний вид, обновите картинки для README:

```powershell
node tools/screenshots.js                       # все сцены
node tools/screenshots.js --only=keys,macros    # выборочно; music-gif собирает GIF
```

Скрипт запускает интерфейс с мок-службой на `127.0.0.1:38590` и снимает его в headless Chrome. Настоящая клавиатура не нужна. Переменные окружения: `CHROME`, `FFMPEG`, `CDP_PORT`, `EXT_CHROME=1`.

## Pull request

1. Сделайте форк и ветку от `main`.
2. Держите изменения небольшими и по одной теме, придерживайтесь стиля кода (см. `.editorconfig`: 2 пробела в JS, `gofmt` для Go).
3. Прогоните тесты и добавьте запись в раздел `CHANGELOG.md`.
4. В описании PR укажите, на какой клавиатуре и в каком подключении проверяли.

## Релиз

1. Обновите `CHANGELOG.md`: новый раздел `## [X.Y.Z] — дата`.
2. `git tag vX.Y.Z` и `git push --tags`.
3. GitHub Actions соберёт exe и zip, посчитает SHA-256 и опубликует релиз с текстом из `CHANGELOG.md`.
